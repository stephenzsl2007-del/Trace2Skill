The learning loop

不是总结，而是验证后再复用

候选 Skill 生成后必须进入未见任务。失败不会被覆盖，而是作为下一版 Skill 的唯一修订依据。

01

真实执行

隔离仓库中诊断、修改并验证 CI 故障。

02

Trace

保存消息、工具、错误、改动与 Validator 结果。

03

Experience

同时消费三条 Trace，结论绑定证据引用。

04

Skill v1

生成六文件、可安装、可审计能力包。

05

Held-out 失败

两个 pnpm 任务暴露 npm-only 假设。

06

Refine

根据失败类别加入包管理器检测与分支。

07

Skill v2

三个 held-out 全部由 Validator 判定通过。

AgentTeams mapping

协作由 Agent 完成，裁决留给程序

AgentTeams 负责角色、任务和上下文流转；Trace2Skill 负责学习闭环；确定性 Validator 拒绝 Agent 自证成功。

ORCHESTRATOR

Manager Agent

拆解阶段任务、分派 Worker、传递有限上下文和产物引用，并追踪每个阶段的状态。

queued → running → validating → succeeded / failed
WORKER 01

Execution Agent

修复隔离 fixture，产生完整执行过程。

WORKER 02

Trace Analyst

从多 Trace 提炼有范围、有证据的 Experience。

WORKER 03

Skill Engineer

生成 v1，再根据失败报告生成 v2。

WORKER 04

Evaluator

组织 held-out 试验，收集但不篡改结果。

DETERMINISTIC HOST

Validator · 唯一裁判

同时检查 install、build、test、原始错误消失和修改边界。
